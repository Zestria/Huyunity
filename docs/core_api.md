# Core API сцены

## Изменение сцены

`huynity::core::Scene` владеет экземплярами сцены. Создание, изменение иерархии,
преобразований, геометрии и визуальных параметров выполняется синхронно на потоке Core.
Методы изменения возвращают `std::expected`; ошибка не должна оставлять частичную мутацию
команды.

`createInstance(source)` разделяет геометрию с исходным объектом и сохраняет его локальную
трансформацию, но создаёт корневой экземпляр без родителя и детей. Мировая трансформация
копии сразу равна локальной; мировые границы пересчитываются при обновлении пространственного
состояния и не наследуют смещение родителя исходного объекта.

Для применения пакета используйте `Scene::apply(std::span<const CommandRequest>)`.
Каждый `CommandRequest` содержит `requestId` и один вариант `Command`: создание объекта или
экземпляра, назначение родителя, изменение transform/geometry/mobility/visibility/material,
удаление поддерева. Результаты возвращаются в порядке входных запросов с тем же `requestId`.
Ошибка одной команды не останавливает обработку остальных. Для команд создания заполненное
`createdObject` содержит новый `ObjectId`; `status` отдельно сообщает успех или ошибку.

```cpp
std::vector<core::CommandRequest> requests{
    {requestId, core::SetVisibilityCommand{id, false}},
};
const auto results = scene.apply(requests);
```

## Чтение для UI

`Scene::view()` создаёт отдельный `SceneView`, содержащий значения идентификаторов,
иерархии, преобразований и визуального состояния. Изменение этого представления не меняет
сцену. Геометрия и материалы передаются как `std::shared_ptr<const ...>`: представление
удерживает неизменяемые ресурсы, но не предоставляет изменяемых ссылок на хранилище Core.

Представление является снимком на момент вызова. Для наблюдения последующих команд UI должен
запросить новое представление после их применения. `Scene::find` остаётся краткосрочным
const-запросом для внутренних синхронных потребителей; отдельный `SceneView` предназначен для
передачи состояния за пределы Core.
